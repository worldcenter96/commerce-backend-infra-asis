## 3. ADR 확인

ADR에서 명시적으로 받아들인 트레이드오프다. 지적하지 않았다.

- ADR-007: 인스턴스·데이터 계층을 AZ-A 한 곳에 둔다. AZ-A 장애 때 3개 서비스가 모두 멈춘다(03 4-4절과 일치).
- ADR-008: RDS Single-AZ, ElastiCache 노드 1개(복제본 없음). 자동 장애 조치가 없고 세션 유실을 허용한다(Q-15).
- ADR-008, 01 2.2: 백업하지 않는다. data.md의 자동 백업 0일, 스냅샷 0일, 최종 스냅샷 없음과 일치한다.
- ADR-008: RDS 7일 뒤 자동 시작. 대비 절차는 05에서 정한다(data.md D-03).
- ADR-004, ADR-011: NAT Gateway 1개(AZ-A). AZ-A 장애 때 아웃바운드와 배포·롤백 경로가 함께 끊긴다.
- ADR-010: NLB를 AZ-A 하나에만 두고 EIP는 1개다. NLB(1 AZ) → ALB(2 AZ) 구성이 동작하는지는 구축 첫날 확인한다(ADR-010, network.md 4.4절 "확인 필요").
- ADR-002: Ubuntu 24.04에서 CodeDeploy 에이전트가 동작하는지 확인하지 않았다(A-06). 구축 첫날 확인한다. 실패할 때의 대체 경로는 REL-02 ⑥에서 따로 지적했다.
- ADR-005: Bastion이 유일한 관리 접속 경로이고 단일 인스턴스다.
- ADR-006: 로그 서버는 단일 인스턴스다.
- ADR-009: Secret 파일을 넣는 방법과 Redis 인증 토큰 사용 여부가 **미정**이다. 05 전에 정하면 되므로 지금 요구사항을 막지 않는다. 다만 배포·롤백과 맞물리는 부분은 REL-02 ⑦에 적었다.

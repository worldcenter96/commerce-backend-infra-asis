## 3. 문제없음 확인

### 기준 1. ADR 정합성
- 5절의 구성 요소는 모두 ADR 또는 고정 제약에 근거가 있다: Route 53(CON-10), ACM·ALB(ADR-003), NLB + EIP(ADR-010, CON-15), VPC·서브넷(ADR-007), EC2 앱 서버(ADR-001), RDS·ElastiCache(ADR-008), NAT Gateway(ADR-004), Bastion(ADR-005), 로그 서버·Alloy(ADR-006), S3·GitHub Actions(CON-09), CodeDeploy(ADR-002), IAM 사용자(CON-13), Secret 파일(ADR-009), Terraform(CON-11). ADR에 없는 구성 요소를 새로 넣지는 않았다.
- ALB 내부용·프라이빗 서브넷 배치, NLB의 TCP 그대로 전달, TLS 종료·호스트 라우팅·`/healthz`를 ALB가 맡는 점이 ADR-003, ADR-010과 같다.
- 인스턴스와 데이터 계층, NAT를 AZ-A에 모으고 AZ-B에는 인스턴스를 두지 않는 배치가 ADR-007과 같다.
- RDS 임시 비밀번호와 변경 감지 제외(4-3 228줄)가 ADR-009와 같다. Secret 파일 주입 방법을 미정으로 둔 점도 ADR-009와 맞다.
- 02 D-04의 S3 게이트웨이 엔드포인트 제안을 ADR에 없으므로 넣지 않고 8절 X-02로 올렸다.

### 기준 2. 요구사항 충족
- 01의 Must 요구사항 18개(FR-02~08, FR-11~13, NFR-02, 04, 06, 07, 11~14)가 6절에 빠짐없이 있다.
- FR-02, FR-03, FR-05, FR-06, FR-07, FR-13, NFR-07, NFR-14의 ○ 판정은 구성 요소와 ADR 근거로 뒷받침된다.
- FR-08, FR-11, NFR-02, NFR-06, NFR-12, NFR-13의 △ 판정과 조건이 ADR 후속 조치·8절 항목과 맞다.

### 기준 3. 흐름의 빈틈
- 4-1은 DNS 조회 → NLB → ALB(TLS 종료 위치 명시) → 앱 → 캐시·DB → 응답까지 이어진다. HTTP(80) 미수신(182줄)도 적혀 있다.
- 4-2는 빌드 → 업로드 → 배포 생성 → 에이전트 폴링 → 설치 → ValidateService → 상태 보고 → ALB 상태 확인까지 이어진다. Secret 파일을 흐름에서 뺀 이유(X-04)를 적었다.
- 4-3은 00·01의 확정 사항(PR 절차 없음, Local State)과 맞게 그렸고, 요청과 다른 이유를 밝혔다.

### 기준 4. 장애 흐름의 정확성
- AZ-A 장애 시 앱 서버, RDS(Single-AZ, 자동 장애 조치 없음), ElastiCache(세션 유실 허용), NAT, Bastion, 로그 서버가 모두 멈추고 3개 서비스가 응답하지 않는다는 결과가 ADR-007·ADR-008의 트레이드오프와 맞다.
- AZ-B 장애 시 AZ-B EIP로 직접 들어오는 연결만 실패하고, 협력사에 EIP 2개를 모두 등록하게 한다는 설명이 ADR-010 후속 조치(49줄)와 맞다.
- 리전 서비스(Route 53, ACM, S3, CodeDeploy)는 AZ 장애와 무관하게 동작한다는 설명이 맞다(일반 지식).
- 복구 절차·RTO/RPO를 정하지 않았다는 점(245줄)을 숨기지 않고 적었다.

### 기준 5. 다이어그램과 본문의 불일치
- Context 다이어그램(37~63줄)과 아래 표(65~72줄)의 외부 대상 6종이 일치한다.
- 4-1, 4-2 시퀀스 다이어그램의 참여자와 단계가 본문 설명(182~183줄, 210~213줄)과 맞다.
- 고정 공인 IP는 들어오는 쪽(NLB)에만 있고 NAT의 EIP는 고정 IP 목적이 아니라는 설명(147줄)이 그림·5절·6절과 일치한다.

### 기준 6. 범위 침범
- CIDR, 포트 번호(“HTTPS 포트”로만 표기), 인스턴스 타입(ADR-001·005·006의 t3.medium·t3.large, ADR-008의 db/cache.t3.micro)을 03에 쓰지 않았다.
- AZ 이름을 AZ-A, AZ-B로 추상화했다(23줄).
- `/healthz` 경로와 Terraform 명령은 01 요구사항(FR-13, FR-11)의 표현을 그대로 쓴 것이라 상세 설정값 침범으로 보지 않았다.

> **읽는 법**
> - 같은 문제를 가리키는 지적은 하나로 합치고 **원래 ID를 모두** 적었다. 통합 ID는 `DR-01`부터다.
> - 리뷰어마다 심각도가 다르면 **가장 높은 심각도**로 분류하고, 차이는 3.2절에 적었다.

> - 문제·제안은 원래 리뷰를 줄여 옮겼다. 자세한 근거는 원래 파일을 본다.
> - **결정** 칸은 비워 두었다. 채택 / 기각 / 수정 중 하나를 적는다.

## 4. ADR 확인 (세 리뷰 공통)

> 세 리뷰어가 ADR에서 받아들인 트레이드오프로 보고 지적하지 않은 항목이다. 겹치는 것은 하나로 합쳤다.

- ADR-001: 서버 크기가 CON-14 "메모리 최소 스펙"과 다르고, 00·01과 02 13절 비용은 고치지 않는다.
- ADR-002: CodeDeploy 구현 난이도 중. Ubuntu 24.04 에이전트 동작은 구축 첫날 확인한다(대체 경로가 없는 점은 DR-03).
- ADR-003: ALB는 중지할 수 없고 TLS를 종료한다. HTTP 80은 리디렉션 없이 거부한다.
- ADR-004·ADR-011: NAT Gateway 1개(AZ-A). AZ-B 프라이빗 서브넷도 이를 쓰고, AZ-A 장애 때 아웃바운드가 끊긴다.
- ADR-005: Bastion SSH가 인터넷에 열리고(출발지 `/32` 제한), 단일 인스턴스다.
- ADR-006: 로그 스택을 자체 호스팅하고(운영 부담 높음), 로그 서버는 단일 인스턴스다.
- ADR-007: 인스턴스와 데이터 계층을 AZ-A에 모아, AZ-A 장애 때 전체가 멈춘다.
- ADR-008: RDS Single-AZ, ElastiCache 노드 1개, 백업 없음, ElastiCache 중지 불가, RDS 7일 뒤 자동 시작(대비 절차는 05).
- ADR-009: Secret 파일을 평문으로 두고, RDS 임시 비밀번호가 State에 남는다.
- ADR-010: 대안 비교 없이 확정. NLB는 TLS를 종료하지 않고 단일 AZ·EIP 1개다. NLB(1 AZ) → ALB(2 AZ) 동작은 구축 첫날 확인한다.
- ADR-011: ALB → 앱 서버 구간은 HTTP다. 모든 SG의 아웃바운드는 전체 허용이다.
- 01 6.1·CON-11: State를 운영자 PC에 암호화 없이 둔다. admin은 외부에 공개하고 WAF는 범위에서 뺐다.

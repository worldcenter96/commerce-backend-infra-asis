# ADR-014. 인스턴스·AZ 배치와 서브넷 구성: 한 AZ에 모으기, /24 안의 용도별 서브넷 8개

| 항목 | 값 |
|---|---|
| 상태 | Accepted (2026-11-15) |
| 대체 대상 | [ADR-012](ADR-012-subnet-layout.md) |
| 결정 지점 | D-07 |
| 날짜 | 2026-11-15 |
| 결정자 | 박가온누리 |
| 근거 문서 | 결정자 서브넷 표(2026-11-14), [04-design/network.md](../04-design/network.md) v1.3 2절, [ai-log](../../ai-log/ai-decisions.md) 2026-11-14 "VPC·서브넷 대역 변경" |

## 맥락

- ADR-012는 인스턴스와 데이터 계층을 AZ-A에 모으고, 서브넷을 용도별로 10개로 나눴다(퍼블릭 3, 프라이빗 7). VPC는 `10.0.0.0/16`이고 계층마다 예비 대역을 뒀다.
- 2026-11-14 결정자가 VPC `192.168.0.0/24`와 /27 서브넷 8개를 지정했다. 이 표에는 public-b(AZ-B 퍼블릭, 예비)와 private-log-a(로그 서버)가 없고, 로그 서버는 앱 서버와 같은 서브넷에 둔다.
- 같은 날 ElastiCache 서브넷 그룹은 서브넷 하나만 쓰기로 했다(network.md N-08).
- 05 AI-08에 따라 ADR-012를 고치지 않고 이 ADR로 대체한다.

## 결정

**인스턴스와 데이터 계층은 AZ-A 한 곳에 모으고(ADR-012와 같음), VPC `192.168.0.0/24`를 /27 서브넷 8개로 나눈다.**

| 서브넷 | 종류 | AZ | 용도 |
|---|---|---|---|
| public-a | 퍼블릭 | AZ-A | Bastion, NAT Gateway |
| public-nlb-a | 퍼블릭 | AZ-A | NLB |
| private-alb-a | 프라이빗 | AZ-A | ALB 노드 |
| private-alb-b | 프라이빗 | AZ-B | ALB 노드 |
| private-app-a | 프라이빗 | AZ-A | 앱 서버 3대, 로그 서버 |
| private-db-a | 프라이빗 | AZ-A | RDS MySQL |
| private-db-b | 프라이빗 | AZ-B | RDS 서브넷 그룹용(인스턴스 없음) |
| private-cache-a | 프라이빗 | AZ-A | ElastiCache Redis(서브넷 그룹도 이 서브넷 하나) |

- CIDR은 04-design/network.md 2절을 따른다. 이 ADR에는 쓰지 않는다.
- AZ-B에는 인스턴스를 두지 않는다. AZ-B 서브넷은 AZ 2개를 요구하는 리소스(ALB, RDS 서브넷 그룹)용이다. AZ-B에는 퍼블릭 서브넷이 없다.
- 로그 서버와 앱 서버의 접근 구분은 서브넷이 아니라 보안 그룹(sg-log, sg-app)으로 한다(security.md P-05).

## 검토한 대안

| 대안 | 내용 | 결과 |
|---|---|---|
| A. ADR-012 유지 | `10.0.0.0/16`, /24 서브넷 10개, 계층별 예비 대역 | 기각(결정자 지정 2026-11-14) |
| B. `192.168.0.0/24`, /27 서브넷 8개 | 위 표 | **채택**(결정자 서브넷 표) |

> 02에서 비교한 대안이 아니다. 결정자 지정으로 정했다.

## 결과

**장점**
- 서브넷이 10개에서 8개로 줄어 라우팅 연결·검증 대상이 줄어든다(설계 리뷰 COST-04, COST-13).
- 서브넷 이름만 보고 어떤 리소스가 있는지 알 수 있다.
- NFR-02, NFR-03, NFR-05를 충족한다. 인스턴스 배치는 ADR-012와 같다.

**단점**
- VPC `192.168.0.0/24`를 서브넷 8개가 모두 써서 예비 대역이 없다. 서브넷을 늘리려면 보조 CIDR을 붙이거나 서브넷을 다시 나눠야 한다(network.md 2절, N-08).
- 서브넷마다 사용 가능 IP가 27개다. ALB 최소 요구(/27, 여유 IP 8개)는 채운다(network.md 2절).
- ElastiCache 서브넷 그룹을 서브넷 하나로 만들 수 없으면 대안 서브넷이 없다(05 R-04).
- 접근 통제는 보안 그룹 참조로만 한다(security.md P-05). 로그 서버가 앱 서버와 같은 서브넷에 있다.
- AZ-A 장애 때 모든 서비스가 멈추는 것은 ADR-012와 같다(00 3.2).

## 맥락

- 3개 서비스의 애플리케이션 로그를 한곳에 모아 서비스별로 조회한다(FR-09, NFR-09).
- 로그 보존 기간은 이번 단계에서 정하지 않는다(Q-32).
- 사용자 선호는 Grafana 스택 자체 호스팅이었고(Q-23), 02에서 자체 호스팅, CloudWatch Logs, Grafana Cloud 무료 플랜을 비교했다.

## 결정

**Grafana Alloy(수집)·Loki(저장)·Grafana(조회)를 자체 호스팅한다.** (02 D-06 대안 A)

- 이유: 자유로운 로그 시각화, 필터링
- 로그(Grafana) 서버 인스턴스 사양: **t3.large**. 결정자 확정(2026-11-12)

## 결과

**장점** (02 D-06 비교표)
- FR-09, NFR-09를 충족한다. 레이블로 서비스를 구분한다.
- 모든 데이터가 서울 리전 안에 있어 NFR-02를 충족한다.
- 중지하면 로그 서버 EBS(20GB)만 과금된다(NFR-13). 상시 과금은 하루 약 $0.06이다.

**단점** (02 D-06 비교표)
- 로그 서버 1대(~~t3.small~~ t3.large, 20GB)가 더 필요하다. 월 최악 약 $20.8로 CloudWatch Logs(약 $1.6)보다 비싸다. 이 금액은 02 비교 당시 t3.small 기준이다(설계 리뷰 DR-20).
- 앱 서버마다 Alloy가 메모리를 약 100~200MB 쓴다(CON-14).
- 운영 부담이 높다. 서버 1대, 저장소, 보존 설정, 화면 접근 경로를 관리해야 한다.
- 구현 난이도가 상이다. 서버 구성, Loki 설정, Alloy 파이프라인, Grafana 접근까지 2일 일정 안에 해야 한다.

**후속 조치**
- Grafana 화면은 Bastion(ADR-005)을 거친 SSH 터널로 접근한다. 03 아키텍처에서 경로를 확정한다.
- ~~로그 서버의 인스턴스 사양에 CON-14가 적용되는지(02 질문 Q-C) 정해야 한다.~~ 로그(Grafana) 서버는 t3.large로 확정했다(2026-11-12).

## 맥락

- 서비스 도메인 3개에서 유효한 인증서로 HTTPS(443)를 받고(FR-02), 도메인별로 해당 서비스에 보낸다(FR-03).
- 진입점은 443만 열고 HTTP(80)는 거부한다(NFR-06, Q-27). 진입점은 `/healthz`로 서비스 상태를 확인한다(FR-13, Q-30).
- 사용자 선호는 ALB였고(Q-23), 02에서 ALB + ACM과 리버스 프록시 EC2(HAProxy + Let's Encrypt)를 비교했다.
- (2026-11-12 추가) 진입점은 고정 공인 IP를 써야 한다(FR-06, Q-36). ALB는 고정 공인 IP를 제공하지 않으므로, 앞단에 NLB + EIP를 둔다([ADR-010](ADR-010-inbound-static-ip.md)).

## 결정

**ALB + ACM을 채택한다.** (02 D-03 대안 A)

- 이유: TLS 증명서를 ACM에 저장해두고 ALB에 가져와서 TLS 복호화
- (2026-11-12 추가) ALB는 NLB([ADR-010](ADR-010-inbound-static-ip.md)) 뒤에 둔다. 사용자 요청은 NLB → ALB 순서로 들어오고, TLS 종료·호스트별 라우팅·`/healthz` 확인은 계속 ALB가 맡는다.
- (2026-11-12 추가) ALB는 **내부용(internal)으로 프라이빗 서브넷**(AZ 2개)에 둔다. 인터넷에서 접근할 수 있는 곳은 NLB까지다. 결정자 지정([ADR-010](ADR-010-inbound-static-ip.md))

## 결과

**장점** (02 D-03 비교표)
- ACM 인증서가 자동으로 갱신된다(FR-02).
- 호스트 헤더 규칙으로 FR-03을, 대상 그룹 상태 확인으로 FR-13을 설정만으로 충족한다.
- 443 리스너만 두고 보안 그룹도 443만 열어 NFR-06을 충족한다. (2026-11-12) ALB 보안 그룹은 NLB에서 오는 트래픽만 허용한다. ALB는 프라이빗 서브넷의 내부용이라 인터넷에서 직접 닿지 않는다.
- 관리형이라 중지할 필요가 없고(NFR-04), 운영 부담이 낮다. ALB 경험이 있어 구현 난이도는 하다(Q-19).

**단점** (02 D-03 비교표)
- 중지 기능이 없다. ALB 시간 요금과 ~~공인 IPv4 2개~~가 계속 과금된다(NFR-13). 상시 과금은 하루 ~~약 $0.78~~ 약 $0.54, 월 최악은 ~~약 $29.6~~ 약 $22.3(LCU 1개 가정)이다. (2026-11-12) 내부용이라 공인 IPv4 요금이 없어졌다(추정치).
- 리버스 프록시(B)보다 하루 약 $0.6 비싸다.

**후속 조치**
- ~~ALB를 인터넷 연결형으로 둘지 내부용으로 둘지 정하지 않았다.~~ 내부용으로 정했다(2026-11-12, ADR-010). 내부용이면 ALB의 공인 IPv4 2개 요금(하루 약 $0.24, 추정치)이 없어진다(03 8절).

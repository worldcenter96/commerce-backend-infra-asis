## 1. 실행 방법

### 1.1 사전 조건 (05 0단계)

- Terraform 1.17.2, AWS CLI 설치
- 운영자 PC에서 루트 계정으로 `aws login`할 수 있어야 한다. Terraform은 루트 계정으로 실행하고 루트 액세스 키는 만들지 않는다(NFR-07·CON-13, 01 v1.5)
- GitHub Actions용 IAM 사용자의 액세스 키(10단계에서 씀). 이 사용자는 Terraform 밖에서 만든다
- 서울 리전에 키 페어 3개가 이미 있어야 한다: `commerce-prod-app-key`(앱 서버 3대), `commerce-prod-log-key`(로그 서버), `commerce-prod-bastion-key`(Bastion). 개인 키는 운영자 PC에만 둔다(ADR-005, compute.md 2절)

### 1.2 자격 증명

자격 증명은 코드와 tfvars에 쓰지 않는다(05 AI-04). 운영자는 루트 계정으로 `aws login`한 뒤 실행한다(결정자 지정 2026-11-15, NFR-07·CON-13). 루트 액세스 키는 만들지 않는다(P-07).

```sh
# (기본) AWS CLI 로그인
aws login
aws sts get-caller-identity     # Arn이 arn:aws:iam::<계정>:root 인지 확인. plan 전에 실행한다
```

- `aws login`을 프로필 이름과 함께 했다면 `export AWS_PROFILE=<프로필 이름>`으로 같은 프로필을 고른다.
- `aws login` 자격 증명을 AWS 프로바이더 6.71.0이 그대로 읽는지는 아직 확인하지 않았다. 첫 `plan`에서 확인한다. 읽지 못하더라도 루트 액세스 키를 만들어 환경 변수로 넣는 방법은 쓰지 않는다(P-07). 그때는 멈추고 결정을 요청한다(05 5.1절).

### 1.3 변수 값 넣기

- `operator_ip_cidr`는 기본값이 없다. `terraform.tfvars.example`을 `terraform.tfvars`로 복사해서 운영자 공인 IP(`<operator-ip>/32`)를 넣는다. `terraform.tfvars`는 Git에 넣지 않는다(05 AI-05, 결정자 지정 2026-11-16).
- 비밀값 변수가 없다. RDS 비밀번호는 RDS 관리형(Secrets Manager)이고 Redis 인증 토큰은 쓰지 않는다(ADR-013).

```sh
cp terraform.tfvars.example terraform.tfvars   # 필요할 때만. terraform.tfvars는 Git에 넣지 않는다
```

### 1.4 명령

```sh
terraform init
terraform fmt -recursive
terraform validate
terraform plan -out=tfplan      # AI가 실행할 수 있는 범위는 여기까지다
terraform apply tfplan          # 운영자만 실행한다 (05 AI-01)
```

- 단계마다 코드 작성 → `fmt`·`validate` → `plan` 결과 요약 → 운영자 확인 → 운영자 `apply` 순서로 한다(05 5.1절).
- `terraform destroy` 전에 아래 3절 "삭제 방법" 열의 수동 작업을 먼저 한다(05 R-11, R-12, R-19).
